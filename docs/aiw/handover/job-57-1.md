## 결정 사항과 이유
- push·배포를 하지 않음: 작업 지시 규칙 "Never push to remote". 운영은 `deploy.sh`가 `git pull --ff-only origin main`으로만 반영하므로 push 없이 배포 불가. 사람이 "main에 커밋까지만 해 두기 (push·배포는 직접)" 선택.
- `pscp` 직접 업로드는 제안만 하고 채택 안 됨: 서버 작업트리가 git과 달라져 이후 `deploy.sh`의 `git pull --ff-only`가 (미추적 파일 `home-popup.blade.php` 덮어쓰기 거부로) 실패하기 때문.
- 팝업 설정은 새 테이블이 아니라 기존 `settings` 테이블의 `site` 키 안 `popup`으로 저장: 마이그레이션 불필요. DB에 저장 전에는 `config/site.php` 기본값이 쓰임(`AppServiceProvider`가 DB `site`를 `config('site')`에 array_merge).
- 팝업 클래스 접두사 `mg-hpop`: 헤더 인기검색어 영역이 이미 `.mg-pop`(`public/css/mango.css` 77~80행, `resources/views/partials/header.blade.php` 59행)을 사용해 충돌했기 때문.
- 이미지 `aspect-ratio` 강제 제거: 1:1 crop 시 원본 상단 문구가 잘려서, 원본 비율 표시로 변경.

## 주의사항·함정
- 로컬 `.env`의 DB가 원격(`3.34.53.36`, DB `mangoshop`)을 가리킴 — 로컬에서 migrate/seed/설정 저장 등 **DB 쓰기 금지**. 지금까지 DB 쓰기는 하지 않았음.
- 현재 작업 폴더 브랜치는 `main`. 작업 지시용으로 만들어진 `aiw/job-57` 브랜치는 사용하지 않았음(`a9327ca`에 머묾).
- 작업 지시 환경에서 PowerShell 툴은 막혀 있음(Bash만 사용 가능). 작업 폴더 밖 경로 접근 불가.
- 헤드리스 크롬은 창 너비를 약 500px 미만으로 줄이지 못함 — 400px 캡처는 잘려 보이지만 레이아웃 문제가 아님.
- tinker로 관리자 뷰를 렌더할 때는 `View::share("errors", new Illuminate\Support\ViewErrorBag)` 필요.
- `deploy.sh`는 기본값 `SEED_PRODUCTS=1`로 `ImportedProductSeeder`를 실행함(기존 동작, idempotent).
- 업로드된 팝업 이미지 경로 `public/product/uploads/`는 `.gitignore` 대상 — 운영 서버에 올린 파일은 서버에만 존재.
- `docs/aiw/outbox/`(캡처 파일)는 커밋에 포함하지 않았음.
